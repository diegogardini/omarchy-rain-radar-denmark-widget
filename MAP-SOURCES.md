# Map sources

The country outlines in `MapData.js` come from [Natural Earth 1:10m Admin 0
countries](https://www.naturalearthdata.com/downloads/10m-cultural-vectors/10m-admin-0-countries/),
via the [Natural Earth vector
repository](https://github.com/nvkelso/natural-earth-vector/blob/master/geojson/ne_10m_admin_0_countries.geojson)
(fetched 2026-09-19). Natural Earth data is [public
domain](https://www.naturalearthdata.com/about/terms-of-use/).
`MapData.js` is generated by `tools/build-map-data.cjs` — don't edit it by
hand.

- **Denmark** (`ISO_A3 == 'DNK'`): all 15 exterior rings (mainland Jutland,
  Zealand, Funen, Bornholm and the other islands), simplified with
  Douglas–Peucker at 0.004° (~400 m, about a quarter of a pixel at the
  panel's normal scale) to ~1,250 points, rounded to 4 decimal places. The
  1:10m source has ~2,200; an earlier version used 1:50m (298 points), which
  lost fjords, inlets and island shapes. Greenland and the Faroe Islands are
  separate territories in Natural Earth and are not included. Interior holes
  (lakes) are not included.
- **Neighbours** (Germany, Sweden, Norway, Poland): context only. Exterior
  rings are clipped to the map domain plus a 0.3° margin (so the artificial
  clip edges fall outside anything drawn) and simplified (Douglas–Peucker,
  the same 0.004°). Norway's ~16,000-point coast is almost entirely outside
  the frame and reduces to a couple of hundred points. All countries come
  from the same source so the shared Danish–German border matches.
- **Labels** are placed by hand on land; `tests/maprange.test.cjs` checks
  each one really falls inside its own country and inside the frame.

## Domain and projection

The map covers `MapModel.bounds` (5.0–16.5°E, 53.9–58.5°N) — see the README
for why it is so much larger than Denmark. `MapModel.js` draws it in a
cosine-scaled equirectangular projection (longitude scaled by cos 56°,
Denmark's mid-latitude) so shapes read correctly rather than looking
unnaturally wide. `helpers/dmi-radar-convert.py` places the DMI radar raster
on this exact same projection (evenly spaced in longitude and latitude) before
it is composited,
so radar and coastlines line up without any runtime reprojection.

The bar icon's peak rain rate is taken over `MapModel.denmarkBounds` (the
Denmark-sized box, 8–15.3°E, 54.3–58°N), a sub-rectangle of the map.

## What this map is and isn't

A regional overview for the radar/forecast overlay, not a precise
administrative boundary and not a radar coverage map. DMI's radar composite
spans roughly 4.4–20.7°E, 52.3–59.8°N, but each radar only sees out to
roughly 240 km, so parts of the frame (e.g. the far north-west North Sea)
have no measurement and render as empty.

## Town search

The panel's town search looks in `Towns.js`: about 9,200 Danish places
(cities, towns, villages, suburbs, quarters and hamlets) with their
coordinates and, where recorded, population, taken from OpenStreetMap with one
Overpass query and built by `tools/build-towns.cjs` (the command is in that
file).

© OpenStreetMap contributors. The list is available under the Open Database
License (ODbL), https://opendatacommons.org/licenses/odbl/; see
https://www.openstreetmap.org/copyright.

GeoNames was tried first and dropped: it lacks real towns (Skærbæk in South
Jutland, about 3,000 people) and records a population for only about 600
Danish places. Denmark's own place-name service (DAWA) has closed.
